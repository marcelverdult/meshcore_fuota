Wo was im Flash liegt

FakeTec und SenseCAP P1 nutzen ein Flash-Layout. Stage-0 liegt direkt hinter dem SoftDevice, danach folgen Status-Seite, Slot A und Slot B. Das Release-Image mit FUOTA belegte am 20. Oktober 2026 270.080 B, also 66 Seiten gemessen.

What lives where in flash

FakeTec and SenseCAP P1 share one flash layout. Stage-0 sits behind the SoftDevice, then come the status page, slot A and slot B. On 20 October 2026 the release image with FUOTA took 270,080 B, which is 66 pages measured.

Aufteilung

Die Boards sind nRF52840 mit Adafruit-Bootloader. Der Bootloader springt ans Ende des SoftDevice, des Bluetooth-Stacks von Nordic. Dort sitzt Stage-0, der Lader, der beim Start die Images tauscht.

  • S140 6.1.1 (FakeTec, RAK4631): Sprungziel 0x26000.
  • S140 7.3.0 (SenseCAP P1, T1000-E): Sprungziel 0x27000.

Ab 0x28000 ist alles für beide gleich. Dort folgen die Status-Seite und zwei Slots mit je 98 Seiten. Eine Seite im Flash sind 4 KB.

  • Slot A enthält die App, das laufende Repeater-Image.
  • Slot B ist das Zwischenlager für den Patch, das Manifest und das neue Image.
  • Der Patch (Delta-Patch) enthält nur den Unterschied zwischen zwei Images.
  • Das Manifest ist die signierte Liste dessen, was zu einem Update gehört.

Layout

The boards are nRF52840 with the Adafruit bootloader. The bootloader jumps to the end of the SoftDevice, Nordic's Bluetooth stack. Stage-0 sits there: the loader that swaps the images at boot.

  • S140 6.1.1 (FakeTec, RAK4631): jump target 0x26000.
  • S140 7.3.0 (SenseCAP P1, T1000-E): jump target 0x27000.

From 0x28000 on, everything is the same for both. The status page follows, then two slots of 98 pages each. A flash page is 4 KB.

  • Slot A contains the app, the running repeater image.
  • Slot B is the staging area for the patch, the manifest and the new image.
  • The patch (delta patch) holds only the difference between two images.
  • The manifest is the signed list of what belongs to an update.

  • Stage-0 writes only to the status page and to both slots checked in the code.

Ein Layout für beide SoftDevice-Versionen

  • Die App ist für 0x29000 gelinkt und nutzt das SoftDevice nicht.
  • Für ein Update per Telefon startet sie neu in den BLE-DFU des Bootloaders.
  • Dasselbe Image läuft darum mit beiden SoftDevice-Versionen.
  • Wir haben ein P1-Image nur mit den Headern von S140 6.1.1 gebaut. Es ist byte-gleich zu dem Image, das auf dem P1 mit S140 7.3.0 läuft gemessen.
  • Ein Repeater-Image läuft nur an der Adresse, für die es gelinkt ist. Darum ist Slot B ein Zwischenlager und kein zweites Startziel.

One layout for both SoftDevice versions

  • The app is linked for 0x29000 and does not use the SoftDevice.
  • For an update by phone it reboots into the BLE DFU of the bootloader.
  • The same image therefore runs with both SoftDevice versions.
  • We built a P1 image with only the S140 6.1.1 headers. It is byte-identical to the image running on the P1 with S140 7.3.0 measured.
  • A repeater image runs only at the address it is linked for. So slot B is a staging area, not a second boot target.

An image may have at most 96 pages. The build stops otherwise measured.

Patch in Slot B

Der Patch liegt seitenbündig am Ende von Slot B. Das neue Image schreibt der Knoten ab dem Anfang von Slot B. Dabei liest er den Patch noch.

Patch in slot B

The patch sits page-aligned at the end of slot B. The node writes the new image from the start of slot B. It is still reading the patch at that moment.

FallWas der Knoten tut
Der Patch passt hinter das größere der beiden Images.Er übersteht den eigenen Tausch, der nur so viele Seiten bewegt wie das größere Image. Der Knoten wendet sofort an und bietet danach weiter an gemessen.
Der Patch passt nicht dahinter.Der Knoten wendet überlappend an. Er kopiert den Patch in Stücken zu 512 Byte ins RAM im Code geprüft. Das neue Image überschreibt nur Patch-Seiten, die er schon ganz gelesen hat.
CaseWhat the node does
The patch fits behind the larger of the two images.It survives its own swap. The swap moves only as many pages as the larger image has. The node applies at once and keeps offering afterwards measured.
The patch does not fit behind.The node applies overlapping. It copies the patch to RAM in chunks of 512 bytes checked in the code. The new image overwrites only patch pages it has read completely.
  • Das Release-Werkzeug spielt genau diesen Code vorher auf dem Rechner durch.
  • Es setzt im signierten Manifest ein Flag, nur wenn das Überlappen sicher ist.
  • Der Knoten hält die Regel beim Anwenden trotzdem selbst ein und bricht sonst ab.
  • Nach dem überlappenden Anwenden ist der Patch weg. Darum gibt der Knoten ihn vorher ein Fenster lang weiter gemessen. Mehr dazu steht unter Ablauf.
  • Ein Patch darf bis zu 64 Seiten groß sein im Code geprüft.
  • Hinter ein Image mit 66 Seiten passen 31 Seiten berechnet. Das sind 98 im Slot, minus 66 fürs Image, minus 1 fürs Manifest. Größere Patches wendet der Knoten überlappend an.
  • The release tool runs exactly this code on a computer beforehand.
  • It sets a flag in the signed manifest only if the overlap is safe.
  • The node still keeps to the rule itself while applying, and stops otherwise.
  • After an overlapping apply the patch is gone. So the node passes it on for a window first measured. More on this under How it runs.
  • A patch may be up to 64 pages checked in the code.
  • 31 pages fit behind an image of 66 pages calculated. The slot has 98 pages, minus 66 for the image, minus 1 for the manifest. The node applies larger patches overlapping.

Ein Image für mehrere Boards

Ein Repeater-Image wählt das Board beim Start. Es läuft auf diesen Boards, alle nRF52840 mit SX1262:

  • auf Hardware getestet: FakeTec, SenseCAP P1, Heltec T114 gemessen
  • gebaut, nicht auf Hardware getestet: RAK4631, Seeed Xiao nRF52840, Heltec T096

Eine Tabelle im Image enthält, was sich je Board unterscheidet:

  • Pins für Funkchip, SPI, I2C, GPS, LEDs, Taste und Batteriemessung
  • TCXO (temperaturkompensierter Quarz), RF-Schalter, DC/DC-Wandler und 32-kHz-Takt
  • Sendeleistung: Vorgabe und Obergrenze, wichtig bei Boards mit Verstärker

Wie das Image sein Board erkennt

  1. Ein Deskriptor von 32 Byte am Ende der Stage-0-Seite nennt das Board. Er enthält Magic-Wert, Version, Board-ID, die Adresse der Seite und die Prüfsumme CRC-32.
  2. Du installierst Stage-0 je Board einmal per USB oder BLE-DFU. FUOTA schreibt diese Seite nie. Ein BLE-DFU ersetzt Stage-0, darum bringt jedes FUOTA-Paket Stage-0 mit gemessen.
  3. Die App liest den Deskriptor an der Adresse, die das SoftDevice als Sprungziel nennt.
  4. Sie vergleicht ihn mit der Board-ID im Bootloader. Nennt der Bootloader ein anderes bekanntes Board, gilt das als Widerspruch.
  5. Ohne Deskriptor reicht die Board-ID nur, wenn der Bootloader zu genau einem Board gehört (P1).

Unbekanntes oder widersprüchliches Board

  • Die App fasst keinen Pin an, sendet nicht und läuft nur im USB-Notbetrieb.
  • Die App bestätigt ein neues Image dann nie. Stage-0 tauscht nach 3 Probestarts ohne Bestätigung zurück.

Die App bestätigt ein neues Image außerdem nur, wenn der Funkchip geantwortet hat. Eine signierte Kampagne (eine Ziel-ID, ein Patch) aktualisiert so FakeTec, SenseCAP P1 und Heltec T114 gemessen.

One image for several boards

One repeater image picks the board at start. It runs on these boards, all nRF52840 with SX1262:

  • tested on hardware: FakeTec, SenseCAP P1, Heltec T114 measured
  • built, not tested on hardware: RAK4631, Seeed Xiao nRF52840, Heltec T096

A table inside the image contains what differs per board:

  • pins of radio chip, SPI, I2C, GPS, LEDs, button and battery measurement
  • TCXO (temperature-compensated crystal), RF switch, DC/DC converter and 32 kHz clock
  • transmit power: default and upper limit, important for boards with an amplifier

How the image recognises its board

  1. A 32-byte descriptor at the end of the Stage-0 page names the board. It contains a magic number, version, board ID, the page address and the CRC-32 checksum.
  2. You install Stage-0 once per board by USB or BLE DFU. FUOTA never writes that page. A BLE DFU replaces Stage-0, so every FUOTA package carries Stage-0 measured.
  3. The app reads the descriptor at the address the SoftDevice names as the jump target.
  4. It compares the descriptor with the board ID in the bootloader. If the bootloader names another known board, that is a contradiction.
  5. Without a descriptor, the board ID can suffice. That holds only if the bootloader belongs to exactly one board (P1).

Unknown or contradictory board

  • The app touches no pin and does not transmit. It runs only in a USB fallback mode.
  • The app then never confirms a new image. Stage-0 reverts after 3 test boots without confirmation.

The app also confirms a new image only if the radio chip answered. One signed campaign (one target ID, one patch) thus updates FakeTec, SenseCAP P1 and Heltec T114 measured.
