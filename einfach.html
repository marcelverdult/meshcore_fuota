Zweiter Alpha-Test im Großraum Hamburg

Du willst testen? Hier starten.

Ein Repeater bekommt das Update von Hand. Alle anderen holen es per Funk.

Repeater sind Funkstationen im MeshCore-Netz. Viele stehen auf Dächern und Masten. Für ein Update musste bisher jemand hinfahren und ein Kabel anstecken. FUOTA heißt Firmware Update Over The Air: Die Repeater geben neue Firmware per Funk weiter. Firmware ist das Programm im Gerät. Alpha heißt: frühe Testfassung. FUOTA ist ein Test und noch nicht Teil von MeshCore.

9 bis 13 StundenSo lange brauchte ein Repeater in den Testläufen, bis er das Update komplett hatte (gemessen). Dazu kommen ab Werk 7 Tage Wartezeit vor dem Einspielen.

5 Wörter, die du brauchst

Alles andere wird dort erklärt, wo es zum ersten Mal vorkommt.

Repeater

Eine Funkstation, oft auf einem Dach oder Mast. Sie gibt Nachrichten im Mesh weiter.

Mesh

Das Funknetz aus allen Repeatern, die sich hören.

Hop

Ein Sprung von einem Repeater zum nächsten. Zwei Hops sind zwei Sprünge.

Fluten

Jeder Repeater gibt die Nachricht an alle weiter, die er hört. So verteilt sie sich wie Wasser.

Seed

Englisch für Saatkorn. Der Repeater, der das neue Release von Hand bekommt. Ein Release ist eine fertige Firmware-Version.

So funktioniert es

Ein Repeater bekommt das neue Release von Hand. Von dort wandert das Update von Repeater zu Repeater.

hat die neue Firmware holt gerade hat noch die alte

Schema, nicht das echte Netz.

  1. 1
    Der Seed bekommt das ReleaseJemand spielt das neue Release von Hand auf einen Repeater, per Kabel oder per Bluetooth. Dieser Repeater heißt Seed. Er bietet das Update seinen Nachbarn an.
  2. 2
    Nachbarn holen nur den UnterschiedÜber Funk geht nur, was sich zwischen alter und neuer Version geändert hat. Bei einem Beispiel waren das 10.076 Byte, rund 10 KB (gemessen). Ein Nachbar holt Datenpaket für Datenpaket. Ein Datenpaket ist ein kleines Funkpaket. Hat er eine ganze Seite (4 KB) zusammen, prüft er sie.
  3. 3
    Jeder gibt es weiterEine geprüfte Seite darf ein Repeater sofort weitergeben, auch wenn ihm noch andere fehlen. So wandert das Update Hop für Hop durchs Mesh.
  4. 4
    Jeder installiert selbstIst alles da, wartet der Repeater ab Werk 7 Tage. In dieser Zeit kann das Update noch zurückgerufen werden. Danach baut er die neue Firmware und startet sie probeweise. Das heißt Probestart. Bestätigt sie sich, bleibt sie. Sonst läuft wieder die alte.

Auch normale Repeater helfen mit

Nicht jeder Repeater im Mesh hat FUOTA. Das Update kann trotzdem durch: Normale Repeater, also Repeater ohne FUOTA, geben Nachrichten und Pakete mit festem Weg weiter.

  1. 1
    Das Angebot wird geflutetDer Anbieter, ein Repeater mit dem Update, ruft in die Runde: „Ich habe ein Update.“ Jeder Repeater, der es hört, gibt es weiter. Das tut der Anbieter in der ersten Woche höchstens einmal am Tag, danach einmal je Woche (im Code geprüft).
  2. 2
    Die Anfrage geht den Weg zurückDas Angebot trägt den Weg, den es genommen hat. Darauf fragt der Empfänger, der Repeater mit Update-Bedarf, zurück: „Schick mir Datenpakete.“ Nicht jeder Weg lässt sich in beide Richtungen nutzen. Bleibt die Anfrage zweimal ohne Antwort, schickt der Empfänger sie einmal als Flut. So lernt der Anbieter einen Weg, der von dort zu ihm führt, und meldet ihn zurück. Danach fragt der Empfänger entlang dieses Weges.
  3. 3
    Die Datenpakete gehen denselben WegNormale Repeater reichen Pakete mit festem Weg weiter wie jedes andere Paket. Dafür brauchen sie kein FUOTA.

Was das kostet: Jeder Repeater auf dem Weg sendet jedes Datenpaket noch einmal. Der Anbieter rechnet das in seine Sendezeit ein (gerechnet: bei k Repeatern dazwischen k + 1 Sendungen je Datenpaket).

Aus dem ersten Test: Das Angebot kam bis zu 6 Hops weit (im Feld beobachtet). Über 2 normale Repeater hintereinander kamen Datenpakete an (im Feld beobachtet). Auf dem Rückweg gingen Anfragen verloren: Nur 35 von 73 gehörten Pfad-Anfragen erreichten den letzten Repeater vor dem Anbieter (im Feld beobachtet). Ein ganzes Update kam auf diesem Weg noch nicht an. Deshalb gibt es die Flut-Anfrage. Ob sie in den Paketen des zweiten Tests steckt, steht beim Release.

Was das Mesh davon merkt

Für Update-Daten darf jeder Repeater höchstens 0,3 % der Zeit senden. Das sind gerechnet rund 11 Sekunden je Stunde. Die Grenze ist im Code fest eingebaut (im Code geprüft).

Daten gehen nur an den, der fragt

Update-Daten werden nie an alle Repeater geschickt. Ein Repeater fragt, und die Daten kommen auf einem festen Weg zu ihm: direkt vom Nachbarn oder über normale Repeater dazwischen.

Normale Nachrichten zuerst

Wartet ein normales Mesh-Paket, geht es vor. FUOTA sendet erst danach.

Wenige Nachrichten gehen an viele

Das Angebot, der Rückruf und der Widerruf eines Schlüssels (ein Release-Schlüssel wird gesperrt) werden geflutet, dazu selten eine Anfrage, die zweimal ohne Antwort blieb. Das Angebot geht in der ersten Woche höchstens einmal am Tag raus, danach einmal je Woche (im Code geprüft).

Wie lange dauert das?

Das Update darf langsam sein. FUOTA sendet so wenig, dass normale Nachrichten Vorrang behalten.

    rund 1 Minute

Zusammen: Holen dauert 9 bis 13 Stunden (gemessen). Dazu kommen ab Werk 7 Tage Wartezeit (im Code festgelegt) und die Bestätigung.

Was deinen Repeater schützt

Diese Vorkehrungen gibt es, und so weit sind sie getestet.

Signierte Firmware

Jedes Release trägt eine digitale Unterschrift. Der Schlüssel dafür liegt offline, getrennt vom Bau der Firmware. Im Code ist festgelegt: Ein Repeater installiert nur Firmware mit passender Unterschrift. Ein Test mit gefälschter Firmware steht noch aus.

Jede Seite wird geprüft

Jede 4-KB-Seite wird mit der unterschriebenen Liste verglichen, bevor ein Repeater sie weitergibt. Ist sie beschädigt, gibt er sie nicht weiter und fragt sie neu an.

Die alte Firmware bleibt als Reserve

Die neue Firmware entsteht neben der alten. Bestätigt sie sich nach 3 Probestarts nicht, läuft wieder die alte (gemessen). Bestätigen heißt: 60 Sekunden gesund laufen, ein Funkpaket hören und eins senden.

Was getestet wurde

Der Repeater wurde im Test 82 Mal mitten im Tausch neu gestartet (Watchdog-Reset, ein Zwangsneustart durch die Geräteüberwachung, gemessen). Danach waren beide Speicherbereiche jedes Mal in Ordnung. Das Kabel mitten im Tausch wirklich zu ziehen, ist nur teilweise getestet. Am Rechner liefen bis 27. Oktober 2026 2,8 Milliarden zufällig veränderte Eingaben ohne Absturz (gemessen).

  1. 1
    VorherSpeicher A läuft mit der alten Firmware. Speicher B hält die neue, geprüfte.
  2. 2
    Tausch und ProbestartDie neue Firmware startet probeweise aus A. Die alte bleibt als Reserve in B.
  3. 3
    Bestätigt oder zurückBestätigt sie sich, bleibt sie. Nach 3 Probestarts ohne Bestätigung wird zurückgetauscht.

Was die Firmware sonst noch kann

Neben dem Update steckt noch mehr in der FUOTA-Firmware. Welche dieser Funktionen in den Paketen des zweiten Tests sind, steht beim Release.

Nebenslot: schnellere Updates

Das Mesh funkt auf einer Frequenz, wie auf einer Straße. Daneben liegen freie Spuren im selben Funkband. Für einen Schwung Daten sagt der Anbieter kurz an. Dann wechseln er und die Nachbarn, denen Daten fehlen, auf eine freie Spur, den Nebenslot. Danach sind alle wieder auf dem Mesh-Kanal. Normale Repeater wechseln nie.

Das Ziel (gerechnet): Ein mittleres Release braucht in Hamburg 1,6 bis 2,7 Stunden statt 27 Stunden. Mehr dazu

Paketfilter: weniger Hops

Ein geflutetes Paket darf nur wenige Hops machen. Normale MeshCore-Repeater erlauben bis zu 64 Hops. Eine Region heißt in MeshCore auch Flood-Scope. Ein Knoten flutet eine Nachricht nur in ihrer Region. Die FUOTA-Firmware erlaubt ab Werk 10 Hops, für Adverts 2 und für Pakete ohne Region 1. Das ist im Code geprüft. Ein Advert ist der Rundruf, mit dem ein Repeater sagt: Ich bin hier. Die kleinen Hop-Grenzen sollen Sendezeit sparen.

Das sind nur Werkswerte. Jeder Repeater-Admin kann sie frei ändern, von 0 bis 64 Hops, zum Beispiel mit set flood.max 64.

Gilt nur für neu installierte Repeater.

Kanalfilter: Vielsender bremsen

Ein Gruppenkanal, zum Beispiel #wetter, ist eine Gruppe, in der Nachrichten laufen. Der Repeater kann einzelne Kanäle auf eine Liste setzen und deren Pakete nicht mehr weitergeben. Er entschlüsselt dabei nichts, er erkennt den Kanal an einer Kennung im Paket.

Im Code geprüft. Auf Funk ist er nicht gemessen.

Stromsparen

Der Befehl powersaving on lässt den Repeater schlafen, wenn nichts zu senden ist. Er kommt aus dem normalen MeshCore und ist ab Werk aus. FUOTA ändert daran nichts. Ein laufendes Update hält den Repeater nicht wach.

Wie viel Strom das spart, ist nicht gemessen.

Dein Test in 6 Schritten

Du brauchst einen Repeater mit nRF52-Chip und Zeit. Zum ersten Aufspielen hast du die Wahl: USB-Kabel oder Bluetooth.

So läuft der zweite Alpha-Test: Die meisten installieren das Basis-Paket. Das Seed-Paket, mit dem das Update startet, bekommt genau ein Gerät je Gruppe. Wer den Seed stellt, sprecht ihr untereinander ab. In deiner Region laufen immer mindestens 2 Test-Repeater, sonst passiert nichts. Alle Schritte stehen auf der Startseite für Tester.

  1. Repeater aussuchen

    Nimm Repeater, an die du gut rankommst und die du entbehren kannst. Es müssen mindestens 2 Test-Repeater in deiner Region laufen, einer davon ist der Seed. Hast du nur einen, such dir Mit-Tester. Welche Geräte (Boards) gehen, steht in der Tabelle auf der Alpha-Seite.

  2. Basis-Paket aufspielen

    Die Basis-Pakete liegen im Release v1.17.1-fuota1, der Seed im Vorab-Release v1.18.0-fuota5. Du hast die Wahl:

    Per USB-Kabel

    Lade die Datei mit deinem Board im Namen. Vergleiche ihre Prüfsumme mit SHA256SUMS aus dem Release. Die Prüfsumme zeigt, dass die Datei beim Laden nicht beschädigt wurde. Schließe das Board per USB an, drück zweimal Reset und zieh die Datei auf das Laufwerk, das dann erscheint.

    Kommst du an das Kabel, nimm diesen Weg.

    Per Bluetooth (OTA)

    OTA heißt: ohne Kabel, per Funk. Du nimmst die ZIP-Datei statt der UF2-Datei. Sie bringt dieselbe Firmware auf einen Repeater, der schon eingerichtet läuft. Mit dem Befehl start ota schaltet der Repeater auf Bluetooth-Update. Bis das Update fertig ist, arbeitet er nicht als Repeater.

    Bei Tests dauerte die Übertragung 135 bis 281 Sekunden. Hat dein Board den Bootloader (das Startprogramm) OTAFIX 1.x, nimm USB. Ob die ZIP-Dateien im Paket liegen, steht beim Release. Mehr dazu

  3. Einrichten

    Per Bluetooth aufgespielt? Dann läuft dein Repeater schon eingerichtet. Funkwerte und Region blieben nach dem Update gleich (gemessen). Du änderst nur noch den Namen: set name FUOTA <Spitzname> <Release>. Schick den Befehl so an den Repeater, wie du es sonst auch tust. Die anderen Befehle in diesem Schritt brauchst du dann nicht.

    Hat dein Repeater noch keine Einstellungen (zum Beispiel direkt nach dem Aufspielen per USB), richte ihn so ein. Öffne die USB-Konsole. Das ist ein Textfenster, in dem du dem Repeater Befehle schickst. Wie du sie öffnest, steht auf der Alpha-Seite. Tippe diese Befehle. Ersetze die Teile in spitzen Klammern.

    password <neues Passwort> set name FUOTA <Spitzname> <Release> region default hansemesh set advert.interval 240 set flood.advert.interval 0 set lat <Breite> set lon <Länge>
    • Passwort: Dieses Passwort legst du neu fest. Höchstens 15 Zeichen. password und ein leeres Passwort gehen nicht.
    • Name: FUOTA, dein Spitzname und die Release-Kennung, zum Beispiel FUOTA verdi 1.17b2. So sieht man im Analyzer (einer Webseite, die das Mesh zeigt), wessen Repeater das ist und welche Version er hat. Die Release-Kennung nennen wir mit den Paketen. Höchstens 31 Zeichen, nicht erlaubt sind [ ] \ : , ? *. Nach einem Update ändert sich die Kennung im Namen nicht von selbst.
    • Advert: Alle 4 Stunden ruft dein Repeater „Ich bin hier“, mit Name und Standort, nur an seine direkten Nachbarn. Der Rundruf an alle (geflutet) ist aus.
    • Standort: Ein grober Standort reicht.
    • Funkwerte: Nimm dieselben wie bei deinen anderen Repeatern: set radio <MHz>,<Bandbreite>,<SF>,<CR>, danach neu starten.
    • Region: der Name der Region, in der dein Repeater Nachrichten flutet. Das Beispiel hansemesh gilt für HanseMesh. Nimm den Namen deines Mesh. Ohne Region meldet dein Repeater seinen Stand nicht, und der Analyzer zeigt ihn nicht in der Ausbreitung des Updates.

  4. Sofort einspielen lassen

    Ab Werk wartet ein Repeater 7 Tage, bevor er ein fertiges Update einspielt. Das kürzt du für den Test ab:

    fuota auto now

    Danach startet der Repeater von selbst neu und ist kurz nicht erreichbar.

  5. Zuschauen

    Mehr musst du nicht tun. Den Stand zeigt fuota info, in der USB-Konsole oder per Fernzugriff übers Mesh, wenn du als Admin angemeldet bist. fuota status zeigt per USB alle Einzelheiten, übers Mesh nur dieselbe Kurzantwort wie fuota info. Von außen siehst du das Update im Analyzer auf der Seite FUOTA-Kampagnen, im Tab Aktivität. Eine Kampagne ist ein Update, das gerade durchs Mesh wandert.

  6. Melden, was passiert ist

    Am liebsten im Telegram-Thread. Dort sprecht ihr auch ab, wer Seed ist. Ein GitHub-Issue mit der Vorlage „Alpha-Bericht“ (dafür brauchst du ein GitHub-Konto) und Discord gehen auch. Wer schon auf dem Server ist, findet die Alpha-Meldungen direkt in diesem Kanal. Kopiere Ausgaben als Text, nicht als Screenshot.

    • Board und Version vorher und nachher (ver, fuota info)
    • wann das Update fertig war und wann die neue Firmware bestätigt war
    • alles Auffällige: Neustarts ohne dein Zutun, Rückfall auf die alte Version, Meldungen mit ERR

Was schiefgehen kann

  • Es ist ein Alpha-Test. Fällt etwas aus, spielst du die Firmware per USB-Kabel neu auf den Repeater. Darum nimm einen Repeater, an den du gut rankommst.
  • Dein Repeater ist kurz weg. Beim Einspielen startet er ohne dein Zutun neu und ist kurz nicht erreichbar. Fällt er auf die alte Firmware zurück, versucht er es frühestens nach 1 Tag erneut.
  • Boards mit dem Bootloader OTAFIX 1.x: Nimm USB statt Bluetooth. Halte das USB-Kabel bereit.
  • Ein Display bleibt dunkel. Die Alpha-Pakete haben keinen Display-Treiber, zum Beispiel am Heltec T114. Das ist so gewollt.
  • Ohne Funkkontakt keine Bestätigung. Hört dein Repeater nach dem Update niemanden, kann er die neue Firmware nicht bestätigen. Nach 3 Probestarts läuft wieder die alte. Stell ihn dahin, wo er andere Repeater hört.
  • Zurück zu MeshCore: Gib in der USB-Konsole fuota uf2 ein. Der Repeater startet neu und erscheint am Rechner als USB-Laufwerk. Zieh die normale MeshCore-Datei (UF2) für dein Board darauf. Antwortet der Repeater nicht mehr, drück zweimal kurz Reset, dann erscheint dasselbe Laufwerk. Ohne USB geht es per Bluetooth: Der Befehl start ota startet den Repeater in den Bluetooth-Update-Modus (auch per Fernzugriff als Admin), dann spielst du das normale MeshCore-Paket ein.

One repeater gets the update by hand. All the others fetch it over the air.

Repeaters are radio stations in the MeshCore network. Many stand on roofs and masts. Until now, an update meant someone had to go there and plug in a cable. FUOTA stands for Firmware Update Over The Air. Repeaters pass new firmware to each other by radio. Firmware is the program inside the device. Alpha means an early test version. FUOTA is a test and not yet part of MeshCore.

5 words you need

Everything else is explained where it first appears.

Repeater

A radio station, often on a roof or mast. It passes messages on in the mesh.

Mesh

The radio network of all repeaters that can hear each other.

Hop

One jump from one repeater to the next. Two hops are two jumps.

Flooding

Every repeater passes the message on to everyone it hears. It spreads like water.

Seed

The repeater that gets the new release by hand. A release is a finished firmware version.

How it works

One repeater gets the new release by hand. From there the update travels from repeater to repeater.

has the new firmware is fetching still has the old one

A diagram, not the real network.

  1. 1
    The seed gets the releaseSomeone puts the new release onto a repeater by hand. That works by cable or over Bluetooth. This repeater is called the seed. It offers the update to its neighbours.
  2. 2
    Neighbours fetch only the differenceOnly what changed between both versions goes over the air. In one example that was 10,076 bytes, about 10 KB (measured). A neighbour fetches it data packet by data packet. A data packet is a small radio packet. Once it has a whole page (4 KB), it checks it.
  3. 3
    Everyone passes it onA repeater may pass on a checked page right away. It may do this while other pages are still missing. This way the update travels hop by hop through the mesh.
  4. 4
    Everyone installs on their ownOnce everything has arrived, the repeater waits 7 days by default. In that time the update can still be recalled. Then it builds the new firmware and starts it on trial. That is called a test boot. If the firmware confirms itself, it stays. Otherwise the old one runs again.

Normal repeaters help too

Not every repeater in the mesh has FUOTA. The update can still get through. Normal repeaters, those without FUOTA, pass on messages and packets with a fixed path.

  1. 1
    The offer is floodedThe provider, a repeater that has the update, calls out “I have an update”. Every repeater that hears it passes it on. In the first week the provider does this at most once a day. After that it does so once a week. Both are checked in the code.
  2. 2
    The request goes back along the pathThe offer carries the path it took. The receiver, the repeater that needs the update, asks back along it: “Send me data packets”. Not every path works in both directions. If the request gets no answer twice, the receiver sends it once as a flood. That way the provider learns a path that leads from there to it. It reports this path back. After that the receiver asks along this path.
  3. 3
    The data packets take the same pathNormal repeaters pass on packets with a fixed path. They treat these like any other packet and do not need FUOTA for that.

What it costs: Every repeater on the path transmits every data packet once more. The provider counts that in its transmit time. With k repeaters in between, a data packet takes k + 1 transmissions (calculated).

From the first test: The offer travelled up to 6 hops through the mesh (observed in the field). Data packets reached a receiver over 2 normal repeaters in a row (observed in the field). Requests were lost on the way back: only 35 of 73 path requests heard reached the last repeater before the provider (observed in the field). No complete update has arrived this way yet. That is why the flooded request exists. The release states whether it is in the second test packages.

What the mesh notices

For update data, each repeater may transmit at most 0.3 % of the time. That is about 11 seconds per hour (calculated). The limit is built into the code (checked in the code).

Data goes only to the one who asks

Update data is never sent to all repeaters. A repeater asks, and the data reaches it along a fixed path. The data comes directly from the neighbour or through normal repeaters in between.

Normal messages first

If a normal mesh packet is waiting, it goes first. FUOTA transmits afterwards.

A few messages go to many

The offer, the recall and the revocation of a key (a release key is blocked) are flooded. Rarely, a request that went unanswered twice is flooded too. In the first week the offer goes out at most once a day. After that it goes out once a week. Both are checked in the code.

How long does it take?

The update is allowed to be slow. FUOTA transmits so little that normal messages keep priority.

    Install and set up

  2. 2 Waiting

    Hear an offer

    up to about 3 days

    A neighbour that has the update offers it. Anyone who joins later hears an offer within about 3 days (checked in the code).

Repeaters further away take longer

Checked pages travel on right away. The next repeater therefore does not wait for the whole update. Each further repeater in the chain adds about 2.5 hours (calculated). This holds if all of them run FUOTA.

What protects your repeater

These safeguards exist, and this is how far they are tested.

Signed firmware

Every release carries a digital signature. The key for it is kept offline, separate from building the firmware. The code says: a repeater installs only firmware with the matching signature. A test with forged firmware is still to come.

Every page is checked

Every 4 KB page is compared with the signed list before it goes on. A damaged page is not passed on. The repeater asks for it again.

The old firmware stays as a reserve

The new firmware is built next to the old one. After 3 test boots without confirmation, the old one runs again (measured). Confirming means: run healthy for 60 seconds, hear one radio packet and send one.

What was tested

In the test the repeater was restarted 82 times during the swap (watchdog reset, a forced restart by the device monitor, measured). Both memory areas were intact every time. Really pulling the cable in the middle of the swap is only partly tested. On a computer, 2.8 billion randomly altered inputs ran without a crash by 27 October 2026 (measured).

  1. 1
    BeforeMemory A runs the old firmware. Memory B holds the new, checked one.
  2. 2
    Swap and test bootThe new firmware starts on trial from A. The old one stays in B as a reserve.
  3. 3
    Confirmed or backIf it confirms itself, it stays. After 3 test boots without confirmation, the repeater swaps back.

What else the firmware can do

The FUOTA firmware holds more than the update. The release states which of these features are in the second test packages.

Side slot: faster updates

The mesh transmits on one frequency, like on a road. Next to it lie free lanes in the same radio band. For a burst of data the provider announces it briefly. Then it and the neighbours that lack data switch to a free lane. That is the side slot. Afterwards everyone is back on the mesh channel. Normal repeaters never switch.

The goal (calculated): a medium-sized release takes 1.6 to 2.7 hours in Hamburg. Without the side slot it takes 27 hours (calculated). More

Packet filter: fewer hops

A flooded packet may make only a few hops. Normal MeshCore repeaters allow up to 64 hops. A region is also called a flood scope in MeshCore. A node floods a message only in its region. The FUOTA firmware allows 10 hops by default. The limit is 2 for adverts and 1 for packets without a region. This is checked in the code. An advert is the broadcast with which a repeater says: I am here. The low hop limits are meant to save airtime.

These are only factory values. Every repeater admin can change them freely, from 0 to 64 hops. An example is set flood.max 64.

Applies only to newly installed repeaters.

Channel filter: slow down chatterboxes

A group channel, for example #wetter, is a group in which messages travel. The repeater can put single channels on a list and stop passing on their packets. It decrypts nothing and recognises the channel by a tag in the packet.

Checked in the code. It is not measured on air.

Power saving

The command powersaving on lets the repeater sleep when there is nothing to send. It comes from regular MeshCore and is off by default. FUOTA does not change it. A running update does not keep the repeater awake.

How much power this saves is not measured.

Your test in 6 steps

You need a repeater with an nRF52 chip and time. For the first install you can choose: USB cable or Bluetooth.

How the second alpha test runs: Most people install the base package. The seed package, which starts the update, goes to exactly one device per group. You agree among yourselves who provides the seed. At least 2 test repeaters always run in your region, otherwise nothing happens. All steps are on the start page for testers.

  1. Pick a repeater

    Take repeaters you can reach easily and can spare. At least 2 test repeaters must run in your region, one of them is the seed. If you have only one, look for fellow testers. Which devices (boards) work is listed in the table on the alpha page.

  2. Install the base package

    The base packages are in the release v1.17.1-fuota1, the seed is in the pre-release v1.18.0-fuota5. You can choose:

    By USB cable

    Download the file with your board in its name. Compare its checksum with SHA256SUMS from the release. The checksum shows that the file was not damaged while downloading. Connect the board by USB and press reset twice. Drag the file onto the drive that appears.

    If you can reach the cable, use this one.

    Over Bluetooth (OTA)

    OTA means: without a cable, by radio. You use the ZIP file instead of the UF2 file. It carries the same firmware onto a repeater that is already set up and running. With the command start ota the repeater switches to Bluetooth update. Until the update is done, it does not work as a repeater.

    In tests the transfer took 135 to 281 seconds. If your board has the OTAFIX 1.x bootloader (the start-up program), use USB. Whether the ZIP files are in the package is stated with the release. More

  3. Set it up

    Installed over Bluetooth? Then your repeater is already set up and running. Radio settings and region stayed the same after the update (measured). You only change the name: set name FUOTA <nickname> <release>. Send the command to the repeater the way you usually do. You do not need the other commands in this step.

    If your repeater has no settings yet, set it up like this. This is the case right after installing by USB, for example. Open the USB console. That is a text window in which you send commands to the repeater. How to open it is explained on the alpha page. Type these commands. Replace the parts in angle brackets.

    password <new password> set name FUOTA <nickname> <release> region default hansemesh set advert.interval 240 set flood.advert.interval 0 set lat <latitude> set lon <longitude>
    • Password: you choose a new password here. At most 15 characters. password and an empty password do not work.
    • Name: FUOTA, your nickname and the release tag, for example FUOTA verdi 1.17b2. In the analyzer (a web page that shows the mesh) you then see whose repeater it is and which version it runs. We will name the release tag with the packages. At most 31 characters; [ ] \ : , ? * are not allowed. After an update the tag in the name does not change by itself.
    • Advert: every 4 hours your repeater calls “I am here”, with name and location. This call goes only to its direct neighbours. The call to everyone (flooded) is off.
    • Location: a rough location is enough.
    • Radio settings: use the same as on your other repeaters: set radio <MHz>,<bandwidth>,<SF>,<CR>, then restart.
    • Region: the name of the region in which your repeater floods messages. The example hansemesh is for HanseMesh. Use the name of your mesh. Without a region your repeater does not report its state. So the analyzer does not show it in the spread of the update.

  4. Install right away

    By default a repeater waits 7 days before it installs a finished update. You shorten that for the test:

    fuota auto now

    After that the repeater restarts on its own and is briefly out of reach.

  5. Watch

    That is all you need to do. fuota info shows the state in the USB console. Over the mesh it works by remote access when you are logged in as admin. fuota status shows all details over USB. Over the mesh it gives only the same short answer as fuota info. From the outside you can see the update in the analyzer. Look in the Activity tab on the FUOTA campaigns page. A campaign is an update that is currently travelling through the mesh.

  6. Report what happened

    Preferably in the Telegram thread. You also agree there who is the seed. A GitHub issue with the template “Alpha-Bericht” (a German template name, you need a GitHub account for it) and Discord work too. If you are already on the server, you find the alpha reports in this channel. Copy output as text, not as screenshots.

    • board and version before and after (ver, fuota info)
    • when the update was complete and when the new firmware was confirmed
    • anything unusual: restarts you did not trigger, fallback to the old version, messages with ERR

What can go wrong

  • It is an alpha test. If something fails, you install the firmware on the repeater again by USB cable. So pick a repeater you can reach easily.
  • Your repeater is briefly gone. While the update is installed, it restarts on its own. It is briefly out of reach. If it falls back, it tries again after 1 day at the earliest.
  • Boards with the OTAFIX 1.x bootloader: Use USB instead of Bluetooth. Keep a USB cable ready.
  • A display stays dark. The alpha packages have no display driver, for example on the Heltec T114. This is intended.
  • No radio contact, no confirmation. If your repeater hears nobody after the update, it cannot confirm the new firmware. After 3 test boots the old one runs again. Place it where it hears other repeaters.
  • Back to MeshCore: Enter fuota uf2 in the USB console. The repeater restarts and shows up on your computer as a USB drive. Drag the regular MeshCore file (UF2) for your board onto it. If the repeater no longer answers, press reset twice in quick succession. Then the same drive appears. Without USB it works over Bluetooth. The command start ota restarts the repeater into the Bluetooth update mode. This also works by remote access as admin. Then you load the regular MeshCore package.
